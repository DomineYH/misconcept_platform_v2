## 0. 핵심 결정

이 프로젝트는 예비교사·현직교사가 오개념을 가진 AI 학생과 수업 대화를 연습하고, 선택적으로 AI 멘토의 도움과 사후 분석을 받는 기존 제품을 개선한다. 새로운 애플리케이션을 처음부터 다시 만드는 작업이 아니다.

| 항목 | 이번 리팩토링의 결정 |
|---|---|
| 제공자 | OpenAI, Anthropic의 Claude, Google의 Gemini를 지원한다. 내부 식별자는 `openai`, `anthropic`, `google`이다. |
| API 키 | 관리자가 웹 화면에서 등록·검증·교체·비활성화한다. 서버가 암호화하여 저장한다. |
| 모델 | 관리자가 사용할 모델을 등록하고, 시나리오 작성 화면에서 학생·멘토·분석 역할별로 선택한다. |
| 시나리오 | 문제 상황, 학생 성향, 멘토 성향, 분석 맥락·기준을 하나의 작성 화면에서 함께 설정한다. |
| 저장 의미 | 별도의 성향·프롬프트·분석 틀을 먼저 저장해 두고 선택하는 방식을 없앤다. 작성한 설정은 **해당 시나리오의 일부로 저장**한다. 비저장·일회성 시나리오를 의미하지 않는다. |
| 비교 | 관리자 전용 2~3개 분할 창에서 동일 입력에 대한 제공자별 응답을 동시에 비교한다. 기본 대상은 학생봇이며 멘토·사후 분석도 동일 비교 화면의 대상 선택으로 지원한다. |
| 영상 | 문제 상황 영상 URL, 영상 대본, 삽입 플레이어, 관련 탭과 실행 로직을 제거한다. |
| 속도 | 학생 응답 스트리밍, 멘토 호출 분리, 매 턴 오개념 분석의 사후 이동, 사후 분석 호출 통합, DB 조회 최적화를 우선한다. |
| 기술 | FastAPI·Jinja2·HTMX·일반 JavaScript·SQLite를 우선 유지한다. 스트리밍 영역만 `fetch` 기반으로 변경한다. |
| 데이터 | 기존 사용자·그룹·대화·분석 결과를 보존한다. 관리자 비교 데이터는 실제 수업 데이터와 분리한다. |

본문의 수치와 정책은 제품 제안값이다. 제공자 성능, 요금, 모델 지원 범위를 보장하는 값이 아니다.

## 1. 배경과 현재 구조

### 1.1 코드에서 확인한 변경 출발점

| 현재 구조 | 리팩토링 필요성 | 근거 |
|---|---|---|

| `StudentBot`, `TutorBot`, 분석 서비스가 OpenAI 전용 호출 구조에 의존한다. | 교육 도메인 로직과 제공자별 요청·응답 처리를 분리한다. | R2, R4, R5 |
| 시나리오가 `student_template_id`, `tutor_template_id`, `framework_id`를 참조한다. 멘토 활성화도 템플릿 연결 여부에 의존한다. | 시나리오 내부 설정과 명시적인 멘토 활성화 값으로 변경한다. | R3 |
| 학생 응답 생성 후 오개념 분석과 튜터 처리를 `asyncio.gather`로 기다리고 나서 학생 메시지를 저장한다. | 이미 일부 병렬화되어 있으므로 단순히 `gather`를 추가하는 것이 해법이 아니다. 학생 응답의 표시·저장을 보조 처리 대기에서 분리한다. | R2 |
| 튜터는 설정에 따라 별도 의미 분석 호출 후 피드백 생성 호출을 할 수 있다. | 개입 판단과 코칭을 한 번의 멘토 호출에서 처리한다. | R4 |
| 사후 분석은 인사 감지, 교사 발화별 분류, 종합 피드백 생성으로 나뉜다. 발화 분류는 최대 5개씩 병렬 호출한다. | 일반 길이 대화는 단일 구조화 출력 호출을 우선 검토한다. | R5 |
| 대화 이력을 전체 조회한 뒤 최근 일부를 Python에서 잘라 사용한다. | 필요한 범위만 DB에서 읽는다. | R2 |
| HTMX 전송 응답과 별도 폴링으로 메시지를 갱신한다. | 스트리밍 중 이중 전송·중복 표시를 없앤다. | R6 |
| `BASE_STUDENT_PROMPT`에 존댓말 강제와 되묻기 금지가 고정되어 있다. | 관리자 성향 설정을 고정 문구가 덮어쓰지 않도록 한다. | R7 |
| 대화 화면에 영상·대본·플레이어가 있다. | 사용자 요청에 따라 제거한다. | R8 |

이 표는 구조 분석이며, 각 항목의 실제 지연 비중을 측정한 결과는 아니다. 구현 전 계측으로 우선순위를 확인한다.

### 1.2 제품 목표

관리자는 코드를 수정하거나 서버의 제공자 API 키 환경변수를 편집하지 않고 AI 연결과 모델 배치를 관리한다. 시나리오는 별도 템플릿 관리 절차 없이 작성하며, 동일 시나리오를 여러 제공자로 시험한 뒤 실제 수업용 모델을 선택한다. 교사는 기존처럼 배정된 시나리오에서 연습하되, 학생 응답을 더 빠르게 확인한다.

### 1.3 유지할 기능

기존 인증, 관리자·교사 권한, 그룹별 시나리오 접근, 대화 이력, 종료된 세션의 조회, 사용자 일괄 등록, 관리자 CSV 내보내기, 실패한 분석의 재시도와 기존 정상 분석 보호를 유지한다. 비교 기능을 위해 교사에게 제공자 설정 권한을 추가하지 않는다.

### 2.2 이번 범위에서 제외

React 전체 재작성, 마이크로서비스, Kubernetes, 별도 AI 에이전트 프레임워크, 벡터 DB·RAG, 파인튜닝, 음성·영상·이미지 생성 및 업로드를 도입하지 않는다. 프롬프트·페르소나 마켓이나 독립 템플릿 보관함도 만들지 않는다.

제공자별 다중 조직·다중 키 라우팅, Azure OpenAI·Bedrock·Vertex AI 연결, 사용자 개인 API 키, 자동 모델 순위·자동 승자 선택, 장애 시 다른 제공자로의 자동 전환은 제외한다. 1차 제공자 연결은 각 서비스의 직접 API와 제공자별 활성 키 1개를 기준으로 한다.

Redis·Celery·PostgreSQL은 선행 필수 조건이 아니다. 초기 배포는 단일 애플리케이션 인스턴스·단일 비동기 워커와 로컬 SQLite를 기준으로 검증한다. 실측 부하로 부족함이 확인되면 별도 확장 과제로 분리한다.

## 3. 사용자와 주요 흐름

### 3.1 관리자

`로그인 → AI 연결·모델 관리 → 제공자 등록·검증 → 사용 모델 활성화 → 시나리오 작성 → 분할 비교 → 모델 적용 → 시나리오 게시`

이미 작성 중인 시나리오에서도 저장 전 비교가 가능하다. 이때 작성 내용을 비교 실행에 필요한 임시 스냅샷으로 저장할 수 있지만, 정식 시나리오나 재사용 템플릿을 자동 생성하지 않는다.

### 3.2 교사

`로그인 → 배정 시나리오 선택 → 문제·공개 학생 정보 확인 → 대화 → 선택적 멘토 도움 → 종료 → 분석 확인`

교사는 API 키, 숨겨진 학생 역할 지시, 분석용 정답 기준, 비교 화면에 접근하지 못한다. 화면 표시 정보와 모델에 전달할 내부 지시는 서버 응답 스키마부터 분리한다.

## 4. F-01/F-02: AI 연결과 모델 관리

### 4.1 제공자 설정 화면

관리자 메뉴에 **‘AI 연결·모델’** 화면을 추가한다. OpenAI, Claude, Gemini를 별도 카드로 표시한다.

| 항목 | 요구사항 |
|---|---|
| API 키 입력 | 새 키를 입력하는 비밀번호형 필드. 저장된 키 원문을 다시 내려주지 않는다. |
| 표시 정보 | 등록 여부, 마스킹 식별자, 활성 상태, 최근 검증 시각, 오류 유형 |
| 동작 | 저장, 연결 확인, 교체, 비활성화, 삭제 |
| 연결 확인 | 모델 조회 등 비생성 확인과, 선택 모델의 실제 응답 시험을 구분한다. 실제 생성 시험은 비용 발생 가능성을 안내하고 별도 클릭으로 실행한다. |
| 오류 | 인증 실패, 권한 부족, 한도·요금제 관련 제한, 모델 접근 불가, 일시 장애를 구분한다. 원문 제공자 오류 전체를 노출하지 않는다. |

키가 없어도 안전한 세션 설정과 DB가 준비되면 관리자 로그인과 설정 화면은 동작해야 한다. 키가 없는 제공자의 모델 실행만 막는다. 이 애플리케이션의 ‘관리자’와 제공자 계정의 조직 관리자는 다른 권한이므로, 모델 호출에 필요한 일반 프로젝트 API 키를 사용하고 불필요한 조직 관리용 키를 요구하지 않는다. 연결 검사 실패가 다른 제공자나 기존 교사 화면 전체의 장애가 되어서는 안 된다.

### 4.2 키 보안

API 키는 호출에 원문이 필요하므로 비밀번호처럼 단방향 해시만 저장해서는 안 된다. 서버에서 검증된 라이브러리의 인증된 암호화 방식으로 저장하고 호출 직전에 복호화한다. 구현 기본안은 AES-256-GCM이며 nonce를 재사용하지 않는다. 암호화 키를 암호문과 함께 DB에 저장하지 않는 원칙을 적용한다. [W10]

마스터 키는 `PROVIDER_SECRET_ENCRYPTION_KEY` 등 서버 환경 설정 또는 배포 비밀 저장소에서 공급한다. 이것은 관리자 화면에서 입력하는 **제공자 API 키와 다른 인프라 비밀**이다. `SESSION_SECRET`과도 분리한다. 자체 암호 알고리즘은 작성하지 않는다.

저장 후 API 키 원문 재조회 API는 만들지 않는다. 브라우저 저장소, URL, HTML 초기 데이터, CSV, 오류 추적, 애플리케이션 로그, Pydantic 검증 오류의 `input` 필드에도 키가 남지 않아야 한다. 입력 중인 필드의 일시적인 원문을 제외하고 브라우저에 보관하지 않으며, 제출 후 지운다.

키 변경·삭제에는 관리자 재인증과 CSRF 검증을 적용한다. 감사 로그에는 관리자, 제공자, 변경 종류, 시각, 비밀을 포함하지 않은 버전 식별자만 기록한다. 암호화 키 누락·복호화 실패 시 임의의 새 키 생성이나 평문 대체 저장을 금지한다. 제공자 호출을 막고 관리자에게 복구 절차를 안내한다.

키 교체 후 시작되는 호출은 새 키를 사용한다. 진행 중 호출은 시작 시 확보한 클라이언트를 사용할 수 있으며, 완료 후 폐기한다. 비활성화 시 새 호출을 즉시 막고 진행 중 호출은 취소를 시도한다. 취소가 이미 발생한 제공자 비용을 되돌린다고 표시하지 않는다.

### 4.3 모델 목록과 등록

각 제공자의 공식 모델 목록 API를 서버에서 조회한다. 목록 조회는 페이지네이션을 처리하며 최근 성공 목록을 캐시하고 수동 새로고침을 제공한다. 초기 캐시 유효기간 제안값은 24시간이다. 갱신 실패 시 기존 목록을 삭제하지 않고 마지막 갱신 시각과 오래된 상태를 표시한다. [W1, W3, W5]

**목록에 존재한다는 사실과 앱의 특정 역할에서 사용할 수 있다는 사실을 구분한다.** 모델 목록만으로 모든 옵션·스트리밍·구조화 출력 지원을 추론하지 않는다. 제공자 메타데이터, 공식 사양에 근거한 작은 기능 정의, 실제 시험 결과를 조합한다.

모델에는 제공자, 원문 모델 ID, 표시 이름, 활성 여부, 지원 기능, 검증 상태, 기본 생성 옵션을 기록한다. 동일 제공자·모델 ID는 중복 등록하지 않는다. 모델 ID를 `gpt-*` 같은 공통 접두사 규칙으로 제한하지 않는다.

목록에 보이지 않는 모델 ID를 관리자가 직접 입력할 수 있으나, **미검증** 상태로 등록한다. 텍스트 생성·스트리밍·필요한 분석 형식 검증이 끝나기 전에는 해당 기능에 배치하지 못한다. 키를 교체하면 접근 권한 검증은 다시 필요하다. 불필요하게 전체 모델을 유료 자동 시험하지 않는다.

### 4.4 역할과 옵션

역할은 학생 `student`, 멘토 `mentor`, 사후 분석 `analysis`의 세 가지로 한정한다. 각 역할은 서로 다른 제공자를 선택할 수 있다. 예를 들어 학생은 Gemini, 멘토는 Claude, 분석은 OpenAI로 배치할 수 있다. 이는 가능한 구성의 예시이지 특정 모델 추천이나 고정 배정이 아니다.

공통 화면에는 제공자·모델, 출력 길이 제한, 지원되는 경우의 생성 다양성·추론 설정을 표시한다. `temperature`, `reasoning`, `thinking`을 모든 제공자에 같은 필드·값으로 전송하지 않는다. 제공자 어댑터가 **선택한 모델이 지원하는 옵션만** 변환한다. 알 수 없거나 지원되지 않는 옵션은 실행 전에 오류로 표시하며 조용히 무시하지 않는다.

모델별 기본값은 시나리오 작성 편의를 위한 값이다. 시나리오 저장 시 유효한 옵션을 확정하여 함께 저장한다. 모델 관리의 기본값 변경은 이미 저장된 시나리오를 자동으로 바꾸지 않는다. 기존 시나리오에는 별도로 수정·저장해야 적용된다.

## 5. F-03/F-07: 시나리오 통합 작성

### 5.1 작성 화면

한 화면 안에 아래 다섯 영역을 배치한다. 긴 화면은 탭 또는 접기·펼치기를 사용하되 별도 설정 페이지로 이동하게 하지 않는다.

| 영역 | 필드와 규칙 |
|---|---|
| 기본 정보 | 제목, 교과, 대상 학년, 배정 그룹, 초안·게시 상태 |
| 문제 상황 | 교사에게 보여 줄 상황·과제, 학습목표, 필요하면 공개 학생 소개 |
| 학생봇 | 이름, 학생 프로필, 목표 오개념, 말투·참여도·반응 길이·되묻기 여부·오개념 변화 조건을 포함하는 행동 지시, 제공자·모델·옵션 |
| 멘토봇 | 사용 여부, 수동·자동 모드, 이름, 성향·코칭 방식·개입 조건·피드백 길이, 호출 간격·횟수 상한, 제공자·모델·옵션 |
| 사후 분석 | 분석 목적, 정답·기대 추론·개념 설명, 평가 맥락, 분류 기준, 피드백 강조점, 제공자·모델·옵션 |

프로필과 행동 지시는 자유 서술을 기본으로 한다. 중요도가 낮은 성격 특성을 수십 개의 개별 DB 컬럼이나 슬라이더로 만들지 않는다. 기본 예시는 작성 필드의 안내문·초기값으로 제공할 수 있으나 별도 이름을 가진 저장·선택형 템플릿으로 만들지 않는다.

분석 분류 기준은 해당 시나리오 안의 작은 편집 표로 제공한다. 각 항목은 `id`, 이름, 설명·판정 기준, 선택적 수준을 가진다. 별도 분석 틀 관리 화면과 `framework_id` 선택은 제거한다. 분류를 사용하는 시나리오는 중복되지 않는 분류 ID와 최소 1개 기준이 필요하다. 분류를 사용하지 않는 경우에도 총평·강점·개선점은 유지한다.

### 5.2 공개 정보와 내부 지시

`problem.public_text`는 교사 화면용이다. `student.misconception`, 상세 행동 지시, 멘토 지시, 분석용 정답·채점 기준은 내부 실행용이다. 공개 문제 상황이 비어 있을 때 내부 프롬프트를 대신 표시하는 폴백은 금지한다.

학생 모델에 멘토의 비공개 판단이나 사후 평가 기준을 함께 전달하지 않는다. 각 역할에 필요한 정보만 전달한다. 사용자 메시지는 역할을 바꾸거나 관리자 지시를 덮어쓰는 설정이 아니라 대화 데이터로 취급한다.

고정된 시스템 보호 규칙은 서버에 남기되 교육적 성향은 시나리오가 결정한다. 기존 ‘존댓말 강제’, ‘되묻기 금지’, 특정 이름 하드코딩은 시나리오 값으로 옮긴다. 관리자가 작성한 텍스트는 코드나 Jinja 템플릿으로 실행하지 않는다. 중괄호가 포함된 수학 표현·JSON 예시도 일반 텍스트로 안전하게 처리한다.

### 5.3 저장·게시·수정

초안은 일부 필드가 빠져도 저장할 수 있다. 게시 전에는 공개 문제, 학생 역할 지시, 활성 학생 모델, 분석 모델과 필수 분석 맥락을 확인한다. 멘토가 켜져 있으면 멘토 지시와 모델도 필요하다. 미검증 또는 비활성 연결이 있으면 게시 또는 신규 실행을 막고 필드 위치를 안내한다.

시나리오 설정은 `config_json`을 단일 실행 원본으로 한다. 검색·권한 필드인 제목, 그룹 연결, 상태 등은 기존 정규 컬럼·관계를 활용한다. 설정 JSON에는 스키마 버전과 검증된 구조를 적용한다. 기존 개별 필드와 JSON을 영구적으로 동시에 읽는 이중 원본 구조는 금지한다.

저장할 때 시나리오 버전을 증가시킨다. 새 세션은 시작 시점의 완성된 설정을 스냅샷으로 저장한다. 진행 중이거나 종료된 세션은 나중에 바뀐 시나리오·모델 기본값의 영향을 받지 않는다. 단, 키 회전·권한 회수·제공자 비활성화 같은 운영 보안 정책은 최신 상태를 적용한다.

동시 편집은 `expected_version`으로 검사한다. 다른 관리자가 먼저 저장한 경우 409를 반환하고 조용히 덮어쓰지 않는다.

### 5.4 영상 제거 범위

관리자 입력 폼, 생성·수정 API 입력, 교사 화면 탭, 플레이어·임베드·YouTube URL 처리, 영상 대본 표시, 관련 테스트·JavaScript를 제거한다. 문제 상황의 텍스트 작성 기능은 유지한다. 시나리오에서 임의 HTML·iframe을 삽입하는 우회 경로도 제공하지 않는다.

이전 영상 필드는 마이그레이션 백업에만 보존한다. 새 실행·화면·API에서 사용하지 않고, 파괴적 컬럼 제거는 데이터 이전 검증과 롤백 단계가 끝난 뒤 수행한다. 영상 대본에만 핵심 문제가 있는 기존 시나리오는 자동 게시하지 않고 ‘문제 상황 보완 필요’로 표시한다.

## 6. F-04: 관리자 모델 비교

### 6.1 화면과 기본 동작

시나리오 작성 화면의 ‘모델 비교’ 버튼 또는 관리자 비교 메뉴에서 연다. 저장된 시나리오와 작성 중 초안을 모두 시험할 수 있다.

| 공통 영역 | 분할 패널 |
|---|---|
| 시나리오·버전 또는 초안 표시 | 제공자와 모델 선택 |
| 비교 대상: 학생 / 멘토 / 분석 | 응답 또는 분석 결과 |
| 동일 입력·맥락 편집 | 대기·생성 중·완료·오류·취소 상태 |
| 동시 실행, 전체 중지, 초기화 | 최초 본문 표시 시간, 완료 시간, 사용량 |
| 비교 방식·조건 차이 안내 | 개별 중지·재시도, 시나리오에 모델 적용 |

데스크톱 1280px 이상에서 세 패널을 가로로 동시에 표시한다. 768~1279px에서는 읽을 수 있는 최소 폭을 유지하며 가로 스크롤을 허용한다. 모바일은 탭 또는 세로 배열을 사용한다. 이는 반응형 표시 차이이며 실행은 동일하게 동시 진행한다.

세 제공자가 준비되면 OpenAI·Claude·Gemini 각 한 패널을 기본으로 한다. 둘만 준비되면 2개 비교를 허용하고 나머지는 미설정으로 표시한다. 다른 제공자를 몰래 대신 사용하지 않는다. 1개만 실행할 때에는 ‘단독 테스트’로 표시한다. 패널 수는 최대 3개다.

### 6.2 비교 대상별 입력

| 대상 | 모든 패널에 공통 전달하는 입력 | 실행 결과 |
|---|---|---|
| 학생 | 문제·프로필·오개념·학생 행동 지시·동일 교사 메시지·기준 대화 이력 | 학생 응답을 패널별 스트리밍 |
| 멘토 | 동일 문제·멘토 지시·교사–학생 대화·개입 정책 | 개입 여부와 코칭 결과. 판단과 코칭은 패널당 1회 호출 |
| 분석 | 동일 종료 대화·정답 맥락·분류 기준·출력 스키마 | 분류·총평·강점·개선점. 완성·검증 전 결과를 확정된 평가로 표시하지 않음 |

학생 비교를 실행했다고 각 패널의 멘토·오개념 분석·사후 분석을 연쇄적으로 호출하지 않는다. **기본 한 번의 학생 비교는 선택된 패널 수만큼의 학생 호출**로 끝난다. 멘토·분석 비교는 관리자가 대상을 바꾸어 명시적으로 실행한다.

### 6.3 비교의 공정성과 대화 이력

기본은 **동일 맥락 비교**다. 각 실행에서 기준 대화 이력, 사용자 입력, 역할 지시의 의미와 순서가 같다. 패널별 생성 결과를 다음 기준 이력에 자동 혼합하지 않는다. 다음 턴에도 엄밀히 같은 맥락을 쓰려면 관리자가 공통 이력에 포함할 응답 한 개를 명시적으로 선택하거나 기준 이력을 편집한다. 이는 비교 실험용 이력 수정이며 원본 수업 대화는 변경하지 않는다.

학생 비교에는 **독립 대화 비교** 모드도 제공한다. 공통 교사 입력을 보내되 각 패널은 자신의 이전 학생 응답만 기억한다. 이 모드는 첫 응답 이후 이력이 달라지므로 ‘동일 입력·서로 다른 누적 대화’라고 명확히 표시한다. 이 모드의 속도·품질 차이를 동일 문맥에서의 순수 모델 차이라고 단정하지 않는다.

동일성은 ‘같은 모델 옵션 값’이 아니라 ‘같은 교육 지시와 내용’을 기준으로 한다. 토크나이저·생성 옵션·추론 기능이 다르므로 옵션 차이와 실제 적용값을 표시한다. 고정 가능한 모델 ID를 우선 사용하되 별칭 모델은 실행 당시 반환 모델 정보를 함께 기록한다. 스냅샷이 있어도 확률적 응답의 완전한 재현을 보장하지 않는다.

입력이 어느 한 모델의 문맥 한도를 초과하면 실행 전 알려야 한다. 특정 패널만 조용히 앞부분을 잘라 보내지 않는다. 관리자가 공통 맥락을 줄인 뒤 다시 실행한다.

### 6.4 실패·취소·재시도

패널별 독립 태스크로 실행하고 실패를 각 패널 내부에서 처리한다. 하나의 실패가 다른 패널을 취소하는 기본 fail-fast 동작은 사용하지 않는다. 전체 완료는 모든 패널이 종료 상태가 된 때이지만 빠른 패널의 결과는 즉시 표시한다.

한 패널이 실패하면 성공한 결과는 그대로 유지하고 실패 패널만 재시도한다. 재시도는 새로운 시도 ID로 기록하며 추가 비용 가능성을 표시한다. 독립 대화 모드에서 실패 패널이 뒤처지면 다음 공통 턴 전에 ‘재시도’ 또는 ‘해당 패널 제외’를 선택하게 한다. 이력이 다른 상태에서 다시 합류하려면 새 비교를 시작한다.

전체·개별 취소는 실제 upstream 요청의 취소를 시도한다. 취소된 응답은 완료 응답으로 간주하지 않으며, 제공자가 확정 사용량을 반환하지 않으면 ‘사용량 미확인’으로 표시한다.

### 6.5 모델 적용과 실험 데이터

패널의 ‘이 모델 적용’은 해당 역할의 제공자·모델·검증된 옵션을 시나리오 편집 폼에 복사한다. 저장 전에는 실제 수업 시나리오를 변경하지 않는다. 자동 승자 선택이나 전체 역할 동시 변경을 하지 않는다.

비교 실행은 일반 `Session`과 별도 식별 공간에서 관리한다. 수업 참여 횟수, 발문 통계, 연구용 기본 CSV, 교사 성취 자료에 섞이지 않는다. 비교 이력에는 관리자, 입력·설정 스냅샷, 대상, 모드, 패널별 결과·실패·시간·사용량을 기록한다. 기본 보존기간 제안값은 30일이며 관리자가 삭제할 수 있다. 만료 데이터는 조회에서 제외하고 운영 정리 명령으로 삭제하며, 실행 주기와 실패 확인 절차를 배포 문서에 기록한다. 비교 데이터를 학습 데이터셋에 자동 편입하지 않는다.

## 7. F-05/F-06: 대화와 분석 처리

### 7.1 학생 응답 경로

`권한·종료 상태·중복 요청 확인 → 교사 메시지와 실행 ID 저장 → 짧은 DB 트랜잭션 종료 → 선택 모델 스트리밍 → 응답 표시 → 최종 학생 메시지 저장 → 완료 이벤트`

학생 생성의 핵심 경로에는 오개념 판별, 멘토 개입 판별, 종합 분석 호출을 넣지 않는다. 화면에는 전송 직후 교사 메시지와 대기 상태를 표시한다. 학생 응답은 공급되는 대로 보여 주고, 최종 저장 성공 이후에만 완료 상태로 전환한다. 저장 실패한 응답을 저장된 것처럼 표시하지 않는다.

같은 세션에서 동시에 두 학생 응답을 생성하지 못하도록 서버가 원자적으로 실행권을 확보한다. 프런트엔드 버튼 비활성화만으로 중복 방지를 구현하지 않는다.

### 7.2 멘토 처리

학생 최종 메시지가 저장된 뒤 별도 멘토 요청을 실행한다. 학생 응답 요청과 멘토 요청의 생명주기를 분리하여 멘토가 느리거나 실패해도 다음 교사 발화를 막지 않는다. 자동 모드는 클라이언트가 서버에 멘토 요청을 보낼 수 있으나, 서버가 설정·중복·횟수 제한을 다시 검사한다.

사용 모드는 `off`, `manual`, `auto`다. 신규 시나리오의 기본 선택은 수동 도움 방식인 `manual`이며 관리자가 끄거나 자동으로 바꿀 수 있다. 저장 시 `enabled=false`와 `mode=off`, `enabled=true`와 `mode=manual|auto`의 일치성을 검증한다. `off`에서는 어떤 멘토·개입 판별 LLM 호출도 하지 않는다. `manual`은 도움 버튼으로 실행한다. `auto`는 호출 간격과 횟수 상한을 먼저 적용한 뒤, 적격 시점에 단일 호출로 `{should_intervene, feedback, reason_summary}`를 생성한다. 별도의 LLM 의미 판별 후 또 피드백을 생성하는 이중 호출은 기본 경로에서 제거한다.

새 시나리오의 자동 모드 제안 기본값은 ‘세 번째 완료 턴부터 검사, 검사 사이 최소 2턴, 최근 10개 완료 턴 안에서 개입 최대 3회’다. 턴은 교사 메시지와 완료된 학생 응답 한 쌍으로 정의한다. 미개입 호출도 검사 간격을 소비하지만 개입 횟수는 소비하지 않는다. 기존 시나리오의 정책은 이전 과정에서 명시적으로 보존·검토한다.

멘토 결과는 대상 `turn_id`에 연결한다. 이후 대화가 진행되어도 결과를 최신 학생 응답인 것처럼 섞지 않는다. 입력 중인 화면을 강제로 이동하거나 사용자의 스크롤을 빼앗지 않는다. 종료 후 도착한 코칭은 종료 시점의 평가 입력에 자동 편입하지 않는다. 실패한 자동 멘토 호출은 반복 재생성하지 않고 수동 재요청을 제공한다.

### 7.3 오개념 분석의 사후 이동

새 표준 경로에서는 매 학생 응답마다 별도 `MisconceptionAnalyzer`를 호출하지 않는다. 오개념 유지·변화·이탈 근거는 사후 분석 결과 안에서 대화의 메시지 ID와 함께 산출한다. 기존 메시지에 저장된 오개념 분석 정보는 보존한다.

이 변경은 기능의 시간적 위치를 바꾸는 정책이다. 실시간 오개념 수치를 계속 수집하는 기존 연구가 있다면 해당 시나리오는 검토 대상으로 표시하고 표준 모드로 자동 전환하지 않는다. 1차 릴리스는 새로운 실시간 연구용 별도 파이프라인을 추가하지 않는다. 기존 실행 경로가 필요한 세션은 전환 전 완료시키거나 읽기 전용으로 종료하는 운영 절차를 사용한다.

### 7.4 사후 분석

일반 길이 대화는 1회의 구조화 출력 호출에서 인사·비분석 발화 구분, 발화 분류, 오개념 변화 근거, 총평·강점·개선점·대안 질문을 함께 반환하도록 한다. 분포·비율은 반환된 유효 분류를 서버가 집계한다. 계산 가능한 통계를 LLM에 다시 요청하지 않는다.

출력에는 `schema_version`, `message_classifications`, `misconception_findings`, `brief_feedback`, `strengths`, `improvements`, `dialogue_coaching`을 포함한다. 원문 메시지 ID·인용문·분류 ID·범위·최소 필드를 검증한다. 존재하지 않는 메시지나 분류를 생성하면 유효 결과로 채택하지 않는다. 인사 여부가 불확실하면 규칙만으로 버리지 않고 분석 대상에 남긴다.

제공자별 구조화 출력 지원 범위가 다르므로 어댑터에서 각 API 형식으로 매핑하고 서버에서 동일 Pydantic 스키마로 최종 검증한다. 거절, 출력 길이 초과, 빈 응답, 스키마 오류를 구분한다. ‘JSON 지원’ 자체가 교육적 판정의 정확성을 보장하지는 않는다. [W7, W8, W9]

분석 결과를 쓰기 전까지 기존 정상 결과는 유지한다. 실패·불완전 결과로 정상 결과를 덮어쓰지 않는다. 신규 분석의 `ok`, `degraded`, `failed` 상태와 재시도 가능 여부를 구분한다. 일부 분류만 유효하다면 분석 범위와 누락을 표시하며, 실패를 빈 분포와 성공 상태로 위장하지 않는다.

단일 호출에 입력 또는 예상 출력이 들어가지 않으면 완전한 교사–학생 턴 단위로 나누어 분류하고, 검증된 중간 결과를 종합하는 제한적 다중 호출로 전환한다. 분할 경계에는 필요한 직전 맥락을 포함하되 분류 담당 메시지 ID는 겹치지 않게 한다. 전체 대화를 몰래 잘라 분석하지 않는다. 출력 예산이 부족하면 실행 전에 범위·분할 계획을 알린다.

## 8. 속도 개선 계획과 측정

### 8.1 우선순위

| 우선순위 | 변경 | 기대 효과 | 검증 방법 |
|---|---|---|---|
| 1 | 학생 본문 스트리밍 및 보조 처리 분리 | 첫 본문 표시와 다음 입력 가능 시점 개선 | 멘토를 인위적으로 늦춰도 학생 표시·저장 완료 시점이 변하지 않는지 검사 |
| 1 | 매 턴 오개념 분석의 사후 이동 | 표준 학생 턴의 필수 생성 호출을 1회로 제한 | 작업 종류별 호출 수 검사 |

| 2 | 최근 이력 DB 범위 조회 | 전체 이력 로딩·메모리 낭비 감소 | 최근 완전한 턴만 조회, 실행계획·이력 크기 증가 테스트 |
| 2 | SDK 클라이언트와 HTTP 연결 재사용 | 매 요청 초기화·연결 비용 축소 | 생명주기·키 교체 테스트, 초기 호출/재사용 호출 구분 |
| 2 | 폴링 중지 | 스트리밍과 중복 요청 제거 | 정상 스트리밍 중 `/messages/updates` 주기 호출 0회 |
| 2 | 모델·옵션 및 출력 길이 조정 | 모델 처리 시간·불필요한 출력 감소 | 동일 교육 품질 기준으로 비교 |
| 3 | 정적 지시 접두부와 설정 캐시 | 반복 설정 조회·프롬프트 처리 감소 | 버전 기반 무효화, 캐시 적중/실패 구분 |

외부 호출 수 축소, 독립 작업 병렬화, 출력 단축과 먼저 보여 주기는 공식 지연 최적화 원칙과도 부합한다. 다만 실제 개선 폭은 측정으로 결정한다. [W11]

### 8.2 문맥 관리

표준 대화는 고정된 시나리오 지시와 최근 완전한 교사–학생 턴을 유지한다. 제안 기본값은 최근 10턴이며 모델별 토큰 한도를 넘지 않도록 출력 여유분을 확보한다. `ORDER BY ... DESC LIMIT ...` 또는 동등한 범위 조회 후 대화 순서로 되돌린다. 첫 역할 지시·핵심 문제를 문맥 절약 때문에 제거하지 않는다.

초기 버전에서는 추가 LLM 요약 호출을 자동 삽입하지 않는다. 제공자별 토큰 계산이 어려우면 보수적으로 추정하고 추정 여부를 기록한다. 비교 모드의 공통 맥락은 패널별로 다르게 절삭하지 않는다.

### 8.3 DB와 캐시

SQLite는 로컬 파일·WAL·짧은 트랜잭션을 기본으로 한다. WAL도 동시에 여러 쓰기를 수행하게 만드는 것은 아니므로 LLM 대기 중 쓰기 잠금을 보유하지 않는다. [W13]

병렬 패널이 동일한 SQLAlchemy `AsyncSession`을 공유하지 않는다. 필요한 입력을 짧게 읽어 일반 데이터 객체로 만든 뒤 외부 호출을 실행하고, 결과 저장마다 독립된 짧은 세션을 사용한다. [W12]

`message(session_id, id)`와 새 턴 조회·실행 ID 조회에 필요한 인덱스를 실행계획을 보고 적용한다. 관리자 목록은 페이지네이션하고 시나리오별 통계를 개별 반복 쿼리로 읽지 않도록 묶어 조회한다. 기존 인덱스와 중복되는 인덱스는 추가하지 않는다.

SDK 클라이언트는 제공자·키 버전별로 재사용하고 FastAPI 생명주기에서 정리한다. 모델별 전역 대화 상태를 보관하는 mutable chat 객체를 사용자 간 공유하지 않는다. 정적 설정 캐시만 우선 사용하고 학생 응답 자체를 사용자 간 재사용하는 답변 캐시는 도입하지 않는다. [W14]

### 8.4 측정 지표와 잠정 목표

| 지표 | 정의 | 잠정 목표·판정 |
|---|---|---|
| 사용자 최초 본문 시간 | 전송 클릭부터 학생의 첫 가시 본문까지. 로딩 표시·빈 이벤트·추론 이벤트는 제외 | 이전 버전 대비 중앙값·p95 개선 확인. 제공자별 별도 보고 |
| 앱 최초 본문 오버헤드 | 외부 제공자의 첫 본문 수신 이후 브라우저 표시까지 | 모의 제공자·기준 환경에서 p95 300ms 이하 |
| 비LLM 화면·API | 모델 외부 호출을 포함하지 않는 관리자 조회·저장 | 기준 환경에서 p95 500ms 이하 |
| 학생 생성 완료 | 학생 최종 본문·메시지 저장 완료까지 | 멘토 지연과 독립적이어야 함 |
| 비교 호출 시작 편차 | 실행 가능 슬롯 확보 후 패널별 외부 호출 시작 시각의 최대 차이 | 모의 환경에서 p95 250ms 이하 |
| 정상 표준 학생 턴 호출 수 | 멘토·분석 제외 학생 생성 | 1회. 명시적 재시도는 별도 집계 |
| 짧은 사후 분석 호출 수 | 입력·출력 예산 안의 분석 | 1회. 실패 재시도·큰 입력 분할은 별도 집계 |
| 구조·근거 검증 | 메시지 ID, 인용, 분류 ID 유효성 | 잘못된 참조를 정상 결과로 저장하는 사례 0건 |
| 중복 처리 | 동일 요청 ID 재전송 | 교사 메시지·학생 최종 응답·새 생성 호출 중복 0건 |

외부 모델 자체의 대기·생성 시간과 로컬 처리 시간, 동시 호출 제한으로 인한 대기 시간을 분리하여 기록한다. ‘모든 제공자가 3초 안에 응답한다’ 같은 보장은 하지 않는다. 전체 시간 목표는 실제 허용 모델을 정한 후 기준선으로 확정한다.

측정은 기준 서버의 CPU·메모리·디스크·Python/SDK 버전·호출 한도와 입력 조건을 기록한다. 모의 제공자로 동시 세션 20개 및 관리자 3패널 1건을 포함한 부하·장애 검사를 수행한다. 처리 슬롯이 부족한 실험의 대기 시간을 제외한 것처럼 보고하지 않는다. 실제 제공자 검사는 승인된 비용 범위 내에서 별도로 수행한다.

스트리밍은 체감 대기 시간을 줄이는 수단이지 모델의 전체 생성 시간을 항상 단축하는 수단이 아니다. 단일 분석 호출·추론 축소·문맥 축소는 고정된 대화 표본으로 교육적 품질 회귀를 확인한 뒤 적용한다.

## 9. 기술 설계 원칙

### 9.1 제공자 어댑터

교육 서비스는 제공자 SDK를 직접 import하지 않고 작은 공통 인터페이스를 사용한다.

```text
제공자 어댑터
  list_models()
  validate_model_and_options()
  generate_text()
  stream_text()
  generate_structured()

공통 요청
  provider, model_id, role, system_instruction,
  messages, validated_options, output_schema, request_id

공통 결과/이벤트
  text_delta, completed, usage, refused, interrupted, error
```

OpenAI는 Responses API, Claude는 Messages API, Gemini는 문서로 지원이 확인된 `generateContent`/`streamGenerateContent`를 기준으로 연결한다. 모든 제공자를 OpenAI 호환 API 하나로 억지 통합하지 않는다. Gemini의 다른 상호작용 API를 채택할 필요가 생기면 어댑터 내부의 명시적 변경으로 검토하고 한 제공자 안에서 두 경로를 조용히 혼용하지 않는다. [W2, W4, W6]

공통 인터페이스는 요청·출력 정규화를 위한 최소 계층이다. 도구 호출·웹 검색·파일 입력·멀티에이전트 런타임까지 포괄하는 범용 프레임워크로 확대하지 않는다. 모든 역할의 호출을 이 경로로 모으고 숨은 OpenAI 전용 폴백을 남기지 않는다.

### 9.2 스트리밍 계약

기존 HTMX는 일반 화면·관리자 CRUD에 유지한다. 생성 요청은 CSRF 헤더를 넣을 수 있는 `fetch` POST와 SSE 형식 응답을 사용한다. 단순 GET 기반 `EventSource`로 쓰기 요청과 비밀 데이터를 전달하지 않는다.

이벤트는 `run.accepted`, `output.delta`, `output.completed`, `run.failed`, `run.cancelled`, `run.interrupted`를 기본으로 한다. 공통 필드는 `run_id`, `turn_id`, 비교일 때 `panel_id`, 단조 증가 `seq`다. 오류·완료·취소는 배타적 종료 상태다. 원문 추론 이벤트를 사용자 응답이나 TTFT에 포함하지 않는다.

`output.delta`는 잠정 표시이며 최종 저장된 내용은 `output.completed`가 확인한다. 완료 이벤트가 오지 않은 채 연결이 끊기면 성공으로 간주하지 않는다. 리버스 프록시 버퍼링·압축 지연을 점검하고 캐시를 금지하며 유휴 연결에는 heartbeat를 적용한다. 모델의 첫 본문 시간과 heartbeat 도착을 구분한다.

구조화된 분석 JSON은 미완성 청크를 그대로 해석하지 않는다. 패널에는 진행 상태를 보여 주고 최종 검증된 결과를 표시한다. 학생 텍스트와 분석 JSON에 동일한 렌더러를 억지 적용하지 않는다.

### 9.3 실행 상태와 중복 방지

요청 ID는 브라우저에서 생성하되 권한과 입력 해시는 서버에서 확인한다. 같은 사용자·대상·요청 ID로 같은 내용을 다시 보내면 새 LLM 호출을 하지 않고 기존 실행 상태를 돌려준다. 다른 내용이면 409다. 동일 세션의 학생 실행권은 DB의 조건부 갱신·유일성 제약으로 확보한다.

실행 상태는 `running`, `completed`, `failed`, `cancelled`, `interrupted`를 사용한다. 실행 시작과 최종 결과를 저장하되 매 토큰마다 DB에 쓰지 않는다. 정상 취소·연결 종료 시 부분 본문을 최선 노력으로 보존할 수 있다. 프로세스 비정상 종료에서 아직 저장하지 않은 부분 토큰까지 복구한다고 보장하지 않는다.

초기 버전의 생성은 요청 생명주기에 묶는다. 브라우저 연결이 끊긴 뒤 생성이 영구적으로 계속된다고 가정하지 않는다. 재시작 시 이전 프로세스의 미완료 실행을 중단 상태로 복구하고 자동 재과금 생성은 하지 않는다. GET 상태 조회로 저장된 결과를 확인한 뒤 사용자가 명시적으로 재시도한다. 상시 폴링은 없으며 재연결 복구 중에만 한시적으로 조회한다.

‘앱의 동일 요청 재전송으로 인한 중복 호출 방지’와 ‘제공자 네트워크 오류 후 정확히 한 번 과금 보장’은 다르다. 후자는 제공자가 명시적으로 보장하지 않으면 보장하지 않는다.

### 9.4 재시도·동시성

재시도는 한 계층만 소유한다. SDK 자동 재시도를 명시적으로 통제해 앱 재시도와 곱해지지 않게 한다. 일시적 네트워크·429·5xx만 제한적으로 재시도하며 `Retry-After`를 존중한다. 인증·권한·유효하지 않은 옵션·정책 거절은 자동 재시도하지 않는다.

비교 실험은 결과와 시간을 흐리지 않도록 자동 생성 재시도 기본값을 0으로 한다. 일반 요청은 첫 본문 전 일시 장애에 한해 최대 1회 재시도를 제안값으로 사용하고 개별 시도와 누적 시간을 기록한다. 본문을 이미 보낸 스트림은 자동으로 처음부터 다시 생성하지 않는다. JSON 검증 실패도 숨은 무제한 재생성 대신 실패·부분 실패와 명시적 재시도로 처리한다.

제공자별·전체 동시 호출 제한을 설정한다. 일반 교사 대화가 관리자 비교에 밀리지 않도록 비교에 최대 3개 슬롯만 사용하게 하고, 관리자당 활성 비교 1건을 기본으로 한다. 무제한 대기열을 만들지 않는다. 슬롯 부족은 제한된 대기 또는 429·재시도 안내로 처리한다. 타임아웃은 연결·첫 본문·전체 요청을 구분하고 역할별로 설정한다.

## 10. 데이터 모델 변경

테이블 이름은 구현 시 기존 명명에 맞출 수 있지만 아래 의미와 제약은 유지한다.

| 엔티티 | 주요 데이터 | 필수 제약 |
|---|---|---|
| `provider_connection` 신규 | provider, encrypted_key, nonce, encryption_key_version, credential_revision, masked_hint, enabled, verified_at, updated_by | 제공자별 활성 설정 1개. 원문 key 반환·로그 금지 |
| `model_config` 신규 | provider_connection_id, model_id, display_name, capabilities_json, default_options_json, enabled, verification_state | 제공자+모델 ID 유일. 참조 중 ID 변경 대신 새 모델 항목 생성 |
| `app_setting` 신규 또는 기존 활용 | 역할별 작성 기본 모델, 동시 호출 한도, 비교 보존기간 | 교육용 프롬프트 저장소로 사용 금지 |
| `scenario` 변경 | 기존 검색·권한 필드, config_schema_version, config_version, config_json, review_required | 실행 설정 단일 원본. 게시 검증 |
| `session` 변경 | config_snapshot_json, config_hash, source_scenario_version, snapshot_origin | 진행 중 설정 변경 금지. 기존 session ID 유지 |
| `message` 변경 | turn_id, turn_index, generation_run_id, 기존 role/content | 멘토와 학생의 소속 턴 식별. 기존 message ID 유지 |
| `comparison_run` 신규 | admin_id, scenario_id nullable, source_snapshot, mode, target_role, canonical_context, context_hash, parent_run_id, expires_at | 일반 session 통계와 분리. 일반 사용자는 접근 불가 |
| `generation_run` 신규 | owner_id, session_id 또는 comparison_run_id, turn_id, panel_id, operation, request_id, input_hash, config_hash, provider/model 스냅샷, 상태, 부분·최종 출력 참조, 시간 | 동일 요청 유일성. 수업/비교 대상 관계 검사. 비교 결과는 여기에 패널별 저장 |
| `api_usage_log` 확장 | run_id, attempt_no, provider, model, operation, input/output/cache/reasoning token 정보, 원본 수치의 허용목록, 추정 비용·단가 기준일 | 정보 없음을 0으로 만들지 않음. 패널·재시도별 사용량 포함 |
| 분석 결과 기존 테이블 확장 | analysis_schema_version, config_hash, analyzed_message_ids, coverage, status | 기존 결과 보존과 검증된 결과의 원자적 교체 |

비교 패널마다 일반 수업 세션을 만들지 않는다. `comparison_run`과 패널별 `generation_run`으로 결과를 관리해 별도의 범용 작업 스케줄러나 실험 관리 플랫폼을 만들지 않는다.

토큰 정의는 제공자마다 다를 수 있다. 입력·출력·캐시·추론 수치의 포함 관계를 어댑터가 문서화하고 중복 합산하지 않는다. 가격이 확인되지 않은 모델은 사용량만 표시하고 비용은 ‘산정 불가’로 둔다. 추정 비용은 실제 청구액과 구분하며, 비용 총합에 미확인 사용량이 있으면 부분 합계임을 표시한다.

### 10.1 시나리오 설정의 논리 구조

```text
config_schema_version
problem
  public_text, learning_objective
student
  name, public_profile, internal_profile, misconception,
  behavior_instruction, resolved_model_config
mentor
  enabled, mode, name, behavior_instruction,
  intervention_policy, resolved_model_config
analysis
  context, expected_understanding, instruction,
  classification_enabled, rubric[], resolved_model_config
runtime
  context_turn_limit, role_timeouts
```

`resolved_model_config`에는 제공자·원문 모델 ID·유효 옵션·참조 모델 ID를 포함하고 API 키는 포함하지 않는다. 설정 해시에도 비밀 키를 넣지 않는다. 런타임은 사용 권한·활성 상태를 확인하되 저장된 모델 ID를 다른 모델로 자동 바꾸지 않는다.

## 11. 내부 API 변경안

기존 인증·권한·URL 관례와 충돌하지 않게 적용하되 의미는 다음과 같다.

| 메서드·경로 | 권한 | 동작 |
|---|---|---|
| `GET /admin/ai/providers` | 관리자 | 비밀을 제외한 연결 상태 |
| `PUT /admin/ai/providers/{provider}` | 재인증 관리자 | 키 저장·교체 및 활성 상태 변경 |
| `DELETE /admin/ai/providers/{provider}` | 재인증 관리자 | 영향 시나리오 안내 후 키 삭제 |
| `POST /admin/ai/providers/{provider}/verify` | 관리자 | 비생성 연결 검사 |
| `POST /admin/ai/providers/{provider}/models/refresh` | 관리자 | 공식 모델 목록 갱신 |
| `GET /admin/ai/models` | 관리자 | 모델·기능·검증 목록 |
| `POST /admin/ai/models` | 관리자 | 사용 모델 또는 직접 입력 모델 등록 |
| `PATCH /admin/ai/models/{id}` | 관리자 | 표시명·활성 여부·기본 옵션 변경 |
| `POST /admin/ai/models/{id}/probe` | 관리자 | 명시적 유료 가능 생성·역할 검증 |
| `PUT /admin/ai/defaults` | 관리자 | 새 시나리오 작성용 역할별 기본값 변경 |
| `POST /admin/scenarios` | 관리자 | 통합 설정으로 시나리오 생성 |
| `POST /admin/scenarios/{id}/update` | 관리자 | 버전 검사 후 통합 설정 수정 |
| `POST /admin/comparisons` | 관리자 | 초안 또는 저장 시나리오의 비교 스냅샷 생성. 생성 호출 없음 |
| `POST /admin/comparisons/{id}/stream` | 소유 관리자 | 선택된 패널의 동시 실행·다중화 스트림 |
| `POST /admin/comparisons/{id}/panels/{panel}/retry` | 소유 관리자 | 실패 패널만 새 시도로 재실행 |
| `POST /sessions/{id}/turns/stream` | 세션 소유 교사 또는 권한 있는 관리자 | 학생 응답 생성·스트리밍 |
| `POST /sessions/{id}/turns/{turn_id}/mentor/stream` | 세션 소유자 | 설정·간격 검사 후 멘토 실행 |
| `POST /sessions/{id}/analyze` | 세션 소유자 | 종료된 세션의 사후 분석 |
| `GET /runs/{run_id}` | 실행 소유자 또는 권한 있는 관리자 | 비밀·내부 지시를 제거한 복구용 상태 |
| `POST /runs/{run_id}/cancel` | 실행 소유자 또는 권한 있는 관리자 | 취소 요청 |

활성 제공자 삭제는 영향받는 시나리오를 명시적으로 경고하고 해당 신규 실행을 차단한다. 다른 제공자로 자동 대체하지 않는다. 일반 사용자가 JSON을 조작해 model/provider를 넘겨도 세션에 저장된 설정만 사용한다. 초안 비교는 관리자 전용 입력 경로를 통해서만 허용한다.

모든 쓰기 요청은 CSRF를 검증한다. 스트림 시작 전 권한 오류는 일반 HTTP 오류로 응답하고 시작 후 오류는 정해진 종료 이벤트로 보낸다. 401, 403, 409, 422, 429 및 제공자 일시 장애를 구분한다.

## 12. 기존 데이터 이전과 전환

### 12.1 이전 원칙

기존 사용자·그룹·시나리오·세션·메시지·분석 ID를 보존한다. 과거 마이그레이션과 고정 baseline SQL은 수정하지 않고 현재 최종 revision 다음의 신규 migration을 추가한다. 실제 운영 DB에 적용하기 전에 복사본에서 검증한다. [R9]

### 12.2 변환 규칙

| 기존 데이터 | 새 구조로의 변환 |
|---|---|
| `problem_situation` | `problem.public_text`로 이동. 없으면 관리자 보완 대상이며 숨겨진 prompt로 대체하지 않음 |
| `student_profile`, `student_name` | 학생 설정으로 이동. 공개·내부 정보의 노출 범위를 검토 |
| `prompt` | 학생 오개념·상황 지시로 보존 |
| 학생 템플릿 참조 | 참조된 실제 텍스트와 알려진 변수 치환 결과를 시나리오 내부 지시로 복사 |
| 고정 학생 행동 규칙 | 기존 시나리오는 이전의 유효 규칙을 함께 보존하되 새 편집 화면에서 수정 가능하게 함 |
| 튜터 템플릿·민감도·횟수 | 멘토 지시와 명시적 enabled/policy로 변환. 단위가 다른 제한은 수동 검토 |
| `analysis_framework` | 이름·분류 ID·기준·수준을 해당 시나리오의 분석 설정으로 복사 |
| 기존 모델 환경변수·시나리오 override | 제공자 OpenAI와 당시 확인 가능한 유효 모델·옵션으로 변환. 확인 불가 값은 검토 필요 |
| `chat_temperature` 등 실제 미적용 옵션 | 이름만 보고 새 엔진에 활성화하지 않음. 이전 유효 동작과 비교하여 선택적으로 이관 |
| `video_url`, `video_transcript` | 이전 백업에만 보존. 새 UI·요청·프롬프트에서 사용하지 않음 |
| 기존 세션·분석 결과 | 그대로 보존. 새 화면의 호환 렌더러로 조회 |

과거 세션에는 실제 시작 시점의 프롬프트·모델 스냅샷이 없을 수 있다. 현재 데이터로 복원한 값을 역사적 사실처럼 표시하지 않는다. `snapshot_origin=legacy_reconstructed`와 복원 시각을 기록하고, 과거 실제 모델·지시를 입증할 수 없는 항목은 ‘알 수 없음’으로 남긴다. 새 세션만 `native` 스냅샷을 보장한다.

누락된 템플릿, 알 수 없는 치환 변수, 영상에만 있는 문제 상황, 미확인 모델, 비어 있는 평가 기준은 자동으로 추측하지 않고 `review_required`로 표시한다. 초안·과거 자료 조회는 가능하지만 검토 없이 신규 수업용으로 게시하지 않는다.

환경변수의 기존 OpenAI 키는 관리자가 새 화면에서 다시 입력하는 것을 기본으로 한다. 필요하면 운영자 승인 하에 1회성 가져오기 도구로 암호화 이전한다. 정상 운영 중 `.env`와 DB 키를 둘 다 읽는 영구 폴백은 만들지 않는다.

### 12.3 단계적 전환

**확장:** 신규 테이블·필드와 변환 코드를 추가하고 기존 필드는 유지한다. 실제 DB 변경 없이 복사본으로 검증한다.

**변환:** 외래키·행 수·메시지 내용·분석 결과·권한·시나리오 매핑을 확인한다. 시작 전 진행 중 세션을 완료시키는 전환 창을 둔다. 진행 중 세션을 새 엔진으로 중간 변경하지 않는다.

**전환:** 관리자에게 검토 대상 시나리오를 제공하고 승인된 시나리오부터 새 실행 경로로 연결한다. 기존 세션은 읽기 전용 조회를 유지한다. 구 시스템·신 시스템이 같은 SQLite 파일에 서로 다른 스키마로 동시에 쓰게 하지 않는다.

**정리:** 새 경로의 회귀·성능·복원 시험 후 템플릿 관리 라우트, 분석 틀 선택 라우트, 관련 실행 참조와 불필요한 필드를 제거한다. `framework_id`의 NOT NULL·외래키와 보고서 조회의 join도 함께 해소한다. 단순히 화면만 숨기지 않는다.

### 12.4 백업과 롤백

SQLite backup API 등 WAL을 포함하는 일관된 방법으로 DB를 백업한다. 암호화된 키를 복구할 수 있도록 해당 암호화 키 버전도 별도 안전한 경로에 보관하고 복원 시험을 한다.

실제 전환 직전 쓰기를 중지하고 스키마·코드 버전을 함께 전환한다. 새 시스템에 쓰기가 발생하기 전 실패하면 검증된 백업과 이전 코드로 되돌린다. 새 시스템에서 쓰기가 발생한 뒤에는 단순히 옛 백업으로 덮어써서 신규 대화를 잃지 않도록, 신규 데이터를 별도 보존·대조한 후 복구 또는 전진 수정한다. ‘언제든 무손실 다운그레이드’라고 보장하지 않는다.

## 13. 보안·오류·데이터 품질

### 13.1 권한과 입력 처리

제공자 설정·비교·시나리오 편집은 서버에서 관리자 권한을 검사한다. 세션·비교·실행 상태 조회는 대상별 소유권을 검사한다. 비활성화·삭제된 시나리오와 종료 세션은 신규 발화를 거부한다. 기존 그룹 접근제어를 우회할 수 없어야 한다.

제공자 연결 주소는 서버의 공식 API 허용목록으로 제한한다. 관리자가 임의 base URL을 입력해 서버 내부망이나 외부 중계로 키를 보내는 기능은 이번 범위에 넣지 않는다. 오류·본문은 XSS 안전한 텍스트 또는 허용목록 기반 Markdown으로 표시한다.

시나리오 입력은 실제 학생의 식별 가능한 개인정보 대신 가명·교육용 페르소나 사용을 안내한다. 비교는 선택한 여러 외부 제공자에 같은 내용이 전송됨을 실행 화면에서 고지한다. 개인정보·보존 정책은 운영기관의 승인된 기준을 적용하며, 제공자들의 보존 정책이 모두 같다고 가정하지 않는다.

### 13.2 실패 시 유지할 상태

| 실패 | 처리 |
|---|---|
| 학생 생성 실패 | 이미 저장된 교사 메시지 유지. 같은 턴에서 명시적으로 재시도 |
| 멘토 실패 | 학생 답변·다음 교사 입력 유지. 멘토만 실패 표시 |
| 한 비교 패널 실패 | 다른 패널의 응답과 사용량 유지 |
| 구조화 출력 거절·손상 | 정상 평가로 저장 금지. 상태와 분석 범위 표시 |
| 재분석 실패 | 이전 정상 보고서와 분류 보존 |
| 키 회수·모델 접근 불가 | 해당 실행 중단·오류 안내. 다른 모델로 무단 전환 금지 |
| 브라우저 재전송 | 동일 실행 조회. 자동 중복 생성 금지 |
| 프로세스 재시작 | 저장된 메시지 유지, 미완료 실행은 중단 상태 복구 |
| 최종 저장 실패 | 화면에서 미저장 상태 표시, 완료 성공으로 취급하지 않음 |

### 13.3 품질 검증

정해진 오개념·학생 성향을 유지하는지, 적절한 교사 개입 후 변화하는지, 멘토가 교사에게 코칭하는지, 분석이 실제 발화를 근거로 하는지 확인한다. 단순한 문법·JSON 성공만으로 교육적 품질을 승인하지 않는다.

서로 다른 교과·오개념·짧은 대화·긴 대화·인사 중심 대화·비생산적 질문·좋은 발문을 포함한 고정 표본을 만든다. 기존 경로와 새 경로를 동일 표본에서 비교한다. 교육 담당자가 오개념 일관성, 역할 충실성, 코칭 유용성, 분석 근거 충실성을 검토한다. 실제 운영 기준을 충족하지 못하면 속도만을 이유로 출력·추론·문맥을 줄이지 않는다.

## 14. 구현 순서와 단계별 완료 조건

각 단계는 작은 변경 묶음으로 구성한다. 위험한 데이터·보안·동시성 변경은 회귀 테스트를 먼저 추가하고, 단순 UI 레이아웃 변경까지 전부 동일한 고강도 TDD 절차를 강제하지 않는다.

| 단계 | 작업 | 완료 조건 |
|---|---|---|
| 0. 기준선 | 현재 실행 경로·테스트·지연 계측, 변경 전 백업·복원 점검 | 핵심 회귀 표본과 측정 방식이 준비됨 |
| 1. UI/UX | 모의 데이터로 제공자 설정, 통합 시나리오 폼, 세 패널 비교, 영상 없는 교사 화면 구현 | 실제 API 키 없이 전체 화면 흐름·실패 상태를 검토할 수 있음 |
| 2. 연결 기반 | 키 암호화, 모델 카탈로그, 제공자 어댑터, 검증·사용량 공통화 | 세 제공자 계약 테스트 통과. 키 없는 앱 부팅과 키 비노출 검증 |
| 3. 시나리오 전환 | 통합 설정·세션 스냅샷·기존 데이터 변환·게시 검증 | 기존 자료 보존, 별도 템플릿 없이 신규 시나리오 생성 가능 |
| 4. 실제 비교 | 동일 맥락·독립 대화, 학생·멘토·분석 대상, 스트리밍·실패 격리 | 3패널 동시 실행·취소·실패 패널 재시도·모델 적용 검증 |
| 5. 대화·속도 | 학생 스트리밍, 멘토 분리, 사후 분석 통합, DB·클라이언트 최적화 | 보조 처리와 학생 완료가 분리되고 품질·성능 회귀 검사 통과 |
| 6. 전환·정리 | 제한 시나리오 검증 후 전환, 레거시 경로 제거, 운영 문서·복구 절차 정리 | 아래 수용 기준 통과 및 운영자 승인 |

단계별 개발 순서는 UI/UX → 실제 기능 연결을 따른다. 실제 수업 데이터에 쓰는 전환은 데이터 이전과 회귀 검증이 끝난 뒤 진행한다. 화면 개발을 먼저 한다는 것이 운영 DB를 먼저 바꾼다는 뜻은 아니다.

CI는 모의 제공자로 계약·상태·보안·마이그레이션을 검사하고 실제 API 키나 과금을 요구하지 않는다. 실제 제공자의 접근·응답·스트리밍 검증은 별도 수동 통합 시험으로 구분하고 승인된 비용 한도를 적용한다.

## 16. 변경 파일 영역과 개발 인계
