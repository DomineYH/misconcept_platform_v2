# 모델 목록과 역할 검증을 분리하고 기존 호출도 공통 연결로 전환한다

제공자 모델 목록은 특정 역할과 옵션의 실행 가능성을 보장하지 않으므로, 목록 등록과 별개로 학생봇·멘토·사후 분석의 역할 검증을 관리한다. 관리자가 비용 발생 가능성을 확인하고 선택한 역할만 시험하며, 공식 근거를 담은 코드 관리 기능 정의가 없는 직접 입력 모델은 등록과 목록 확인까지만 허용한다. 기능 정의와 제공자 메타데이터가 충돌하면 생성 시험과 실행을 막는다.

S1에서 기존 학생·멘토·사후 분석 호출도 DB 자격 증명과 공통 제공자 어댑터로 전환한다. 기존 OpenAI 모델 ID와 옵션은 유지하고 같은 모델의 등록·역할 검증 전까지 실행을 막는다. 관리자 시험만 새 경로를 쓰고 기존 호출에 환경 변수 키 경로를 남기는 이중 운영은 하지 않는다.

## Consequences

- 역할 검증은 미검증·검증 중·성공·실패·재검증 필요를 구분한다. 목록에서 찾았다는 이유만으로 검증을 생략하지 않는다.
- 검증 효력은 자격 증명 버전에 연결한다. 키 교체·삭제는 효력을 무효화하고 비활성화는 재검증 필요로 바꾼다. 재활성화만으로 실행을 허용하지 않으며 이전 키의 늦은 시험 결과가 새 키의 검증 상태를 덮어쓰지 못하게 한다. 교체 전에 시작한 일반 호출은 기존 키로 완료할 수 있다.
- 역할별 기본 모델은 새 시나리오 작성 편의에만 사용한다. 활성 상태이며 해당 역할 검증에 성공한 모델만 지정할 수 있고, 이후 사용 불가가 되면 그 상태를 표시한다. 기존 시나리오·세션을 바꾸거나 다른 모델로 자동 대체하지 않는다.
- 시나리오별 제공자 선택과 설정 스냅샷은 S2, 멘토·사후 분석의 새 동작은 S3/S4에서 다룬다. S1은 자격 증명·호출·검증 경계를 전환하면서 기존 교육 동작을 보존한다.
- 검증은 자격 증명·기능 정의·역할 출력 계약의 버전에 종속된다. 기능이나 계약이 바뀌면 재검증하며, 이미 지원되는 범위 안의 기본 옵션 변경은 정적 검증으로 처리한다. 시험 성공은 교육적 품질 보증이 아니다.

## Adapter boundary

OpenAI Responses, Anthropic Messages, Gemini generateContent를 각 공식 SDK로 연결한다. S1 기준 SDK는 각각 3.26.0, 1.12.1, 2.29.0이다. Gemini Interactions로의 전환은 현재 텍스트·구조화 출력 요구에 필요한 이득이 확인되지 않았으므로 기존 조사와 PRD의 지원되는 경로를 유지한다.

SDK 자동 재시도는 끄고 공통 호출 계층이 시간 제한·동시 호출 한도·시도별 사용량을 관리한다. 학생·멘토는 S0의 자동 재시도 0회를 유지하고 분석만 일시 장애에 최대 1회 재시도한다. 관리자 생성 시험과 향후 비교도 자동 재시도하지 않는다. 토큰이나 비용을 모르면 0이나 다른 모델의 단가로 대체하지 않는다.
