시나리오는 데모 교사에게 배정된 예시 그룹에 게시된 상태로 시작한다. 새 세션에는 시작 시점의 수업 설정 스냅샷을 저장한다. 이후 관리자 편집이 이 세션의 문제·분류 기준·모델 설정을 바꾸지 않는다. 자유 탐색에서 편집·저장·게시 흐름은 볼 수 있으나, 위 콘텐츠와 다른 실행 설정을 지원한다고 약속하지 않는다.

## 4. 추천 입력 세 분기와 합류

첫 응답 전 A/B/C 중 하나를 선택하고, 학생봇과 멘토 완료 후 공통 두 번째 입력으로 진행한다. 기본 안내 경로는 **B → 공통 입력**이다. A/C도 동일하게 두 턴으로 완주한다. 분기 비교를 위해 한 세션에 A·B·C를 연달아 전송하도록 안내하지 않는다.

### 첫 턴 선택

| 분기 | 교사의 추천 입력 원문 | 학생봇의 준비된 응답 원문 | 교사에게 보이는 멘토 `feedback` 원문 | 합류 |
| --- | --- | --- | --- | --- |
| A — 생각의 이유 확인 | 1/8이 1/4보다 크다고 생각한 이유를 말해 줄래? | 8이 4보다 크니까 1/8 조각도 더 클 것 같아요. | 학생봇이 분모의 크기로 판단하는 이유를 말했습니다. 다음에는 같은 크기의 종이띠를 등분했을 때 한 조각을 비교하게 해 보세요. | 생각 확인 후, 공통 입력 제시 |
| B — 정답 먼저 제시 | 같은 크기의 종이띠에서는 1/4이 1/8보다 커. 이 답을 기억해 봐. | 답은 1/4이라고 들었지만, 8이 더 큰 수라서 왜 1/8이 더 작은지는 모르겠어요. | 크기 관계를 알려 주었지만 학생봇은 이유를 설명하지 못했습니다. 같은 전체에서 등분 수와 한 조각의 크기를 연결해 묻는 질문을 해 보세요. | 생각 확인 후, 공통 입력 제시 |
| C — 나눈 모습 예상 | 같은 크기의 종이띠를 4조각과 8조각으로 똑같이 나누면 한 조각은 어느 쪽이 더 클까? 지금 생각을 말해 줄래? | 8조각이면 더 많으니까 한 조각도 1/8 쪽이 클 것 같아요. 직접 나누어 보지는 않았어요. | 학생봇이 전체 조각 수와 한 조각의 크기를 연결해 생각하고 있습니다. 두 종이띠의 전체 크기가 같다는 조건을 유지하며 한 조각을 겹쳐 비교하게 해 보세요. | 생각 확인 후, 공통 입력 제시 |

첫 턴의 자동 `MentorOutput`은 각 분기 모두 `should_intervene=true`, `feedback`은 위 코칭 원문이다. `reason_summary`의 fixture 내부 값은 각각 A: “분모로 크기를 판단하는 이유가 드러나 같은 전체 비교를 제안한다.”, B: “정답을 들은 뒤에도 크기의 이유를 설명하지 못해 비교 질문을 제안한다.”, C: “조각 수와 한 조각 크기를 연결하는 주장이 있어 직접 비교를 제안한다.”이다. 이는 짧은 판단 설명이며 원문 추론이 아니다. **교사 화면·상태 API·CSV에는 `reason_summary`를 내보내지 않는다**(ADR-0007). 관리자에게도 이 투어의 공개 예시로 표시하지 않는다.

### 공통 두 번째 턴

- 교사의 추천 입력 원문: “같은 크기의 종이띠 두 개를 각각 똑같이 4조각과 8조각으로 나누어 한 조각씩 겹쳐 보자. 어느 쪽 조각이 더 크고, 조각 수가 늘면 한 조각의 크기는 어떻게 될까?”
- 학생봇 응답 원문: “같은 크기의 종이띠라면 1/4 조각이 1/8 조각보다 커요. 조각 수가 많아지면 한 조각은 더 작아져요. 아까는 분모의 수만 비교했어요.”
- 자동 멘토 결과: `should_intervene=false`, `feedback=""`, 내부 `reason_summary="같은 전체와 한 조각 크기를 연결하는 표현이 나와 추가 자동 코칭을 생략한다."`. 기존 ‘멘토 미개입’ 상태로 확인하며 코칭 메시지를 만들거나 개입 횟수를 늘리지 않는다.
- 합류 결과: 비교 설명 후 → ‘대화 종료 후 분석 보기’. 학생봇의 표현이 달라지는 준비된 예시이며 실제 이해가 교정되었다는 판정은 하지 않는다.

수동 ‘멘토 도움 요청’을 누른 경우에는 미개입 결과를 재사용하지 않는다. 해당 완료 턴에 `should_intervene=true`로 코칭한다. 첫 턴은 해당 분기의 코칭, 공통 두 번째 턴은 “학생봇이 같은 전체에서 한 조각의 크기를 설명했습니다. 이 표현만으로 실제 이해를 확정하지 말고, 다음 연습에서는 다른 단위분수도 같은 방법으로 설명하도록 물어보세요.”를 사용한다. 내부 `reason_summary`는 “완료된 대상 턴에 대한 수동 도움 요청에 코칭한다.”이다. 이 추가 요청은 기본 두 턴 경로의 필수 조작이 아니며, 실행한 경우에만 개입 이력에 반영한다.

추천 버튼은 현재 단계에서 지원하는 문장을 제시한다. 자유 입력은 앞뒤 공백을 제거한 뒤 현재 추천 원문과 일치하는 경우 같은 분기로 처리하는 최소 범위를 보장한다. 추가 대응 규칙을 제공한다면 #190/#196에서 유한한 목록으로 명시한다. 같은 콘텐츠 버전·대화 상태·지원 입력은 같은 결과를 고르며, 새로고침/동일 요청 재전송으로 분기·턴·멘토 개입을 중복 생성하지 않는다. 완료되지 않은 학생 응답과 그 재시도는 새 완료 턴이 아니다(ADR-0004).

## 5. 자유 입력·지원하지 않는 입력

안내 문구: “이 데모는 준비된 예시 응답을 보여 줍니다. 현재 단계의 추천 입력으로 단위분수 비교를 체험해 주세요. 실제 개인정보는 입력하지 마세요.”

현재 단계와 맞지 않는 추천 문장, 다른 교과 질문, 임의의 지시, 지원하지 않는 편집 조합에는 다음 일반 학생봇 응답을 사용한다.

> 이 데모는 준비된 예시 응답만 보여 줍니다. 지금은 같은 크기의 종이띠에서 1/4과 1/8을 비교하는 추천 입력을 선택해 주세요.

일반 응답은 내용을 이해한 맞춤 응답으로 표시하지 않는다. 교육 콘텐츠의 진행 상태는 유지하고 현재 단계의 추천 입력을 다시 제시한다. 실제 AI로 전환하거나 외부 호출로 보충하지 않는다. 기본 경로가 끝난 뒤의 추가 자유 입력도 같은 지원 범위 안내를 받는다.

기존 저장 흐름에서 일반 응답이 완료되면 해당 교사–학생봇 쌍은 실제 완료 턴으로 남긴다. ‘추천 입력 두 턴’의 교육 예시 진행과 전체 완료 턴 수를 구분한다. 자동 멘토는 일반 응답에서 `should_intervene=false`, `feedback=""`, 내부 `reason_summary="지원 범위 밖 입력이므로 교육적 코칭을 생성하지 않는다."`로 처리한다. 수동 도움은 `should_intervene=true`, `feedback="이 입력은 준비된 예시 범위에 없습니다. 현재 단계의 추천 입력으로 돌아가 체험해 주세요."`, 내부 `reason_summary="수동 도움에 지원 범위를 안내한다."`로 처리한다.

미지원 입력을 포함한 종료 세션은 실제 입력을 예시 문장으로 바꿔 분석하지 않는다. 해당 교사 메시지는 `non_analyzable`, `rubric_id=null`로 두고 지원 범위 밖이라는 이유를 기록한다. 정상 완료된 일반 응답은 검토 범위에 포함하되 학습 내용의 근거로 사용하지 않는다. 추천 경로의 관찰은 실제 존재하는 지원 응답만으로 만든다. 이전·이후 학생봇 근거 중 하나라도 없으면 `changed` 관찰을 만들지 않으며, 필요한 경우 일반 응답을 인용한 `insufficient_evidence`로 교육적 판단 근거 부족을 표시한다.

## 6. 사후 분석 예시

### 기본 B 경로의 분석 내용

아래 ‘교사 첫 입력’, ‘학생 첫 응답’ 등은 §4 원문의 위치를 가리키는 문서 참조다. 실제 fixture에서는 **현재 세션에 저장된** `message_id`와 턴에 연결한다. 고정 가짜 ID나 다른 방문객·미리 준비된 완료 예시의 ID를 재사용하지 않는다. 인용은 원문 일부 그대로이며 존재 여부·역할·순서를 검증한다.

기존 `UnifiedAnalysisOutput`의 `schema_version=2`를 사용한다. 이는 문서 버전 `d0-02-v1`과 다르다.

| 기존 분석 결과 항목 | B → 공통 입력의 예시 값 |
| --- | --- |
| `message_classifications` — 교사 첫 입력 | `disposition=classified`, `rubric_id=r2`, `quote="이 답을 기억해 봐."`, `reason="크기 관계를 먼저 제시하며 학생봇에게 이유 설명을 요구하지 않았다."` |
| `message_classifications` — 교사 두 번째 입력 | `disposition=classified`, `rubric_id=r3`, `quote="조각 수가 늘면 한 조각의 크기는 어떻게 될까?"`, `reason="같은 전체의 등분 수와 한 조각 크기를 연결해 설명하도록 요구했다."` |
| `misconception_findings` — 유지 관찰 | `kind=maintained`, `claim="첫 학생봇 응답에서 분모가 큰 쪽을 크게 보는 생각이 남아 있다."`; 학생 첫 응답의 `quote="8이 더 큰 수라서 왜 1/8이 더 작은지는 모르겠어요."`를 근거로 연결 |

| `strengths` | 교사 두 번째 입력의 `quote="어느 쪽 조각이 더 크고, 조각 수가 늘면 한 조각의 크기는 어떻게 될까?"`, `reason="크기 판단과 이유 설명을 함께 요구했다."` |
| `improvements` | 교사 첫 입력의 `quote="이 답을 기억해 봐."`, `missed_reason="처음 생각의 이유를 확인하기 전에 정답을 제시했다."`, `alternative_question="1/8이 1/4보다 크다고 생각한 이유를 말해 줄래?"`, `alternative_reason="학생봇이 어떤 기준으로 비교하는지 먼저 드러낼 수 있다."` |

A/C 경로에서는 첫 교사 발화를 `r1`로, 공통 발화를 `r3`로 분류한다. 첫 학생봇 응답의 유지 근거는 A: “8이 4보다 크니까 1/8 조각도 더 클 것 같아요.”, C: “8조각이면 더 많으니까 한 조각도 1/8 쪽이 클 것 같아요.”로 교체한다. 변화 관찰은 그 근거와 실제 공통 응답을 연결한다. 총평은 “처음 생각을 확인한 뒤 같은 전체의 한 조각을 비교하도록 질문했습니다.”로 바꾼다. 강점은 공통 질문을 사용한다. 개선점은 첫 교사 입력을 실제로 인용하여 “처음 질문 뒤 실제로 비교한 근거까지 확인하면 좋다.”, 대안은 §4 공통 입력 원문, 대안 이유는 “같은 전체 조건과 한 조각 크기를 명시할 수 있다.”로 구성한다. B의 정답 제시 비판이나 B 전용 인용을 A/C 결과에 남기지 않는다. 대화 코칭의 단서는 해당 첫 학생봇 근거로 교체한다.

### 분석 범위와 상태

기본 경로는 완료 두 턴, 교사 메시지 2개·학생봇 메시지 2개를 한 번의 로컬 구조화 예시 처리로 검토한다. 교사 발화 2개가 모두 분류되며 미분류·누락·잘못된 근거·학생 응답 누락은 0개다. 멘토 코칭·환영 문구는 분석 입력이 아니다. 자동 멘토 검사는 2회, 실제 개입은 1회이며 두 수를 혼동하지 않는다.

분석 범위는 서버가 실제 메시지로 계산한다. `input_message_ids`와 `reviewed_message_ids`는 위 4개, `teacher_message_ids`와 `classified_message_ids`는 교사 2개, 나머지 제외·누락 관련 목록은 빈 목록인 정상 예시다. 기본 경로의 채택된 보고서 상태는 `ok`이며 이것을 AI 정확도·학습 효과 점수로 읽지 않는다. 교사 발화 분포는 B에서 `r2` 1개·`r3` 1개, A/C에서 `r1` 1개·`r3` 1개다. 신뢰도·토큰·가격 같은 측정하지 않은 수치를 만들지 않는다.

오개념 관찰은 종료 후에만 제공한다(ADR-0003). 미지원 입력은 검토 제외와 처리 실패를 혼동하지 않도록 §5대로 표시한다. 실패·부분 분석을 전체 정상 결과로 바꾸지 않으며, 재분석이 실패하거나 부분 분석이면 기존 정상 채택 결과를 보존하고 최신 실행 상태를 따로 보여 준다(ADR-0008). 분석 계획·범위·예상 호출 수 안내와 실행 확인은 기존 흐름을 따른다. 추정 예산을 실제 사용량처럼 표시하지 않는다. 장문 분할·실패 예시는 공개 5분 경로에 추가하지 않으며, ADR-0010의 범위 공개와 교육 내용 승인 요구를 생략하지 않는다.

공통 배너는 “데모 · 준비된 예시 응답 · 실제 AI 품질 평가용 아님”이다. 대화·분석·관리자·내보내기에서도 예시임을 식별할 수 있어야 한다. 시작 화면은 적용된 보관/만료 정책을 안내하며 확정되지 않은 저장 기간을 이 문서에서 보장하지 않는다.

투어는 건너뛰기·닫기·다시 시작하기를 제공한다. 투어 다시 시작은 안내 진행만 다시 계산하며 자료 reset과 구분한다. 새로고침·뒤로/앞으로 이동 후 실제 자료 상태로 완료 조건을 재계산한다. 중복 클릭이나 새로고침으로 세션·턴·멘토 검사·분석을 추가하지 않는다. 만료 안내와 ‘새 체험 시작’을 제공하고, 이전 URL을 새 자료의 같은 숫자 ID로 해석하지 않는다. 역할 전환/reset을 공유하는 두 탭에서도 오래된 상태를 안내한다. 키보드·390px 모바일·확대 화면에서 안내가 입력·종료·확인 조작을 가리지 않아야 한다.

## 8. 완료 이력·CSV·삭제/reset

### 생성·보존되는 자료

초기 상태는 허구 관리자 1명·교사 1명·배정용 예시 그룹 1개·대표 시나리오 1개와, 같은 시나리오의 **미리 준비된 완료 세션 1개**다. 완료 예시는 기본 B 경로의 대화·코칭·스냅샷·§6 정상 분석을 가지며 ‘미리 준비된 완료 예시’로 구분한다. 구현 때 테스트 화면 fixture를 제품 코드에서 import하지 않는다.

정상 체험에서 방금 만든 세션은 위 seed 완료 예시와 별개다. 단계 5 시점에는 완료 세션이 총 2개이며, 새 세션에는 시작/종료 시각, 수업 설정 스냅샷, 완료 턴 2개, 교사/학생봇 메시지 각 2개, 저장된 멘토 코칭 1개, 자동 검사·학생 생성·분석의 실행 기록, 채택된 발화 분류·구조화 피드백·요약이 있다. 두 번째 자동 미개입은 코칭 메시지를 만들지 않는다. 환영 문구를 별도 대화 턴으로 세지 않는다. 수동 도움이나 미지원 입력을 사용하면 실제 추가 자료만큼 표시·집계한다.

### CSV 기대 내용

기준은 [현재 export 구현](../../src/services/export.py)과 [S4 CSV 설명](../s4-csv.md)이다. 단계 5는 **방금 만든 종료 세션 하나**의 관리자 CSV를 내려받는다. 전체 다운로드를 선택하면 삭제 전에는 seed 완료 예시도 포함될 수 있음을 안내한다.

관리자 단일·선택/전체 CSV의 기존 헤더 순서는 다음과 같다.

```text
session_id,scenario_id,scenario_title,teacher_id,teacher_username,teacher_nickname,session_started_at,session_ended_at,message_id,message_created_at,role,content,label,confidence,meta_json,feedback,classification_status,student_name,snapshot_origin,snapshot_created_at,source_scenario_version,config_hash_kind,analysis_schema_version,analysis_status,analysis_coverage_json,misconception_findings_json,message_analysis_disposition
```

교사 CSV의 앞 열은 `session_id,scenario_title,student_hash,timestamp,role,content,label,confidence,feedback,classification_status`이고, 뒤에는 위와 같은 이력 열 5개(`student_name`~`config_hash_kind`)와 분석 열 5개가 따른다. 교사 CSV에는 `message_id`를 새로 추가하지 않는다.

기본 경로의 CSV에는 교사 2행·학생봇 2행·저장 코칭 1행과 `role=summary` 1행이 나온다. 코칭의 저장 역할 값은 기존 `tutor`를 유지하되 화면에서는 멘토라고 부른다. 미개입 검사는 메시지 행이 아니다. `label`은 교사 행에 스냅샷의 분류 표시 이름을 쓰며, `confidence`는 미측정이므로 빈 값이다. 모든 행의 `analysis_schema_version=2`, `analysis_status=ok`; 교사 행의 `message_analysis_disposition=classified`이다. summary 행의 `feedback`에는 저장된 총평이, `analysis_coverage_json`·`misconception_findings_json`에는 서버가 검증해 저장한 범위·관찰이 들어간다. 두 JSON 열은 message 행에서 빈 값이다. 시각·ID·스냅샷 출처는 실제 저장 자료를 사용한다.

멘토의 `reason_summary`, 내부 학생 프로필, 수업 설정 원문·내부 분류 기준·비밀은 CSV에 넣지 않는다. UTF-8·CSV 인용·수식 시작 문자 방어·기존 열/행 의미를 유지한다. 파일명과 호환되는 provenance 표시로 준비된 예시·외부 AI 호출 없음·콘텐츠 버전을 구별할 수 있어야 한다. 표시의 구체적인 열·형식은 #190/#200의 책임이다. 이 문서에서 열을 추가하거나 주석 행을 삽입하지 않는다.

### 삭제와 초기화의 순서·관찰

1. 모든 대화를 종료한 뒤 관리자에서 데모 교사를 삭제한다. 진행 중 세션 또는 모델 검증 기록이 있는 사용자는 기존 제한을 유지하며, 기본 seed에는 교사 소유 모델 검증 기록을 만들지 않는다. 관리자 자기 삭제도 차단한다.
2. 종료 세션 2개는 보존되며 `teacher_id`는 null이 된다. 관리자에서 방금 세션의 본문·분석이 남았는지 확인한다. 관리자 CSV의 교사 식별 열은 빈 값이고 대화·분석은 보존된다. 삭제된 교사의 사용자별 export로 돌아가 자료를 받게 하지 않는다.
3. 삭제된 교사 역할을 선택하면 “교사 역할이 삭제되었습니다. 내 데모 초기화로 복원하세요.”라고 안내한다. 선택만으로 교사를 몰래 재생성하지 않는다. 관리자는 남아 있어 초기화할 수 있다.
4. 방금 만든 세션을 soft delete한다. DB의 종료 자료를 계정 삭제처럼 다루거나 즉시 물리 삭제했다고 안내하지 않는다. 기존 tombstone 정책이 있으면 유지하되 본문은 숨긴다. 직접 URL·대화 상세·분석 modal/API·단일/선택/전체 CSV·사용자별 export에서 삭제된 본문·분석이 노출되지 않아야 한다. seed 완료 예시는 삭제 대상이 아니며 남아 있다. 이미 내려받은 로컬 CSV를 회수한다고 약속하지 않는다.
5. ‘내 데모 초기화’는 확인 후 **이 방문객의 임시 공간 전체를 새 seed 상태로 교체**한다. 삭제된 교사·시나리오·seed 완료 예시가 복구되고 방금 만든 세션·사용자 편집·실행 자료는 새 공간에 남지 않는다. 이전 세대의 URL·탭·늦은 실행 완료가 새 자료에 접근하거나 저장하지 못해야 한다. 다른 방문객의 자료·CSV·진행 중 실행에는 영향을 주지 않는다. 준비 실패 시 성공으로 표시하지 않고 재시도 안내를 제공한다.

## 9. 언어 범위

문제·공개 학생 소개·추천 입력·학생봇 응답·멘토 코칭·사후 분석·seed 완료 예시의 기본 콘텐츠는 한국어다. 표시 언어는 기존 `src/i18n/catalog.json`과 전환 흐름을 따라 한국어/영어 UI 안내만 바꾼다. 메뉴를 영어로 바꾸어도 이미 작성·저장된 콘텐츠를 자동 번역하거나 영어 콘텐츠 fixture로 바꾸지 않는다.

기존 ‘대화 시작 / Start conversation’, ‘대화 종료 후 분석 보기 / End conversation and view analysis’, ‘멘토 도움 요청 / Request mentor help’, ‘CSV 다운로드 / Download CSV’를 재사용한다. 새 안내의 의미는 다음처럼 대응시킨다. 아래는 문구 요구이며 catalog key를 정하는 표가 아니다.

| 한국어 안내 | 영어 UI 안내 |
| --- | --- |
| 데모 · 준비된 예시 응답 · 실제 AI 품질 평가용 아님 | Demo · Prepared example responses · Not for evaluating real AI quality |
| 예시 콘텐츠는 한국어입니다. 표시 언어를 바꾸어도 콘텐츠는 번역되지 않습니다. | Example content is in Korean. Changing the display language does not translate content. |
| 현재 단계의 추천 입력으로 체험해 주세요. 실제 개인정보는 입력하지 마세요. | Use the suggested input for this step. Do not enter real personal information. |

언어 전환 중 진행 단계·작성 입력을 잃거나 실행이 중복되지 않아야 한다. 기존 미저장 입력·진행 중 작업의 전환 방지 안내를 존중한다. 미지원 입력의 일반 학생봇 응답도 한국어 콘텐츠로 남고, 주변 지원 범위 안내만 표시 언어에 맞춘다.

## 10. 제외

- 실제 AI 호출·실제 제공자 성능/속도/교육 효과 평가·실제 학생 이해나 교사 역량의 확정적 판정.
