# 턴의 정체성과 응답 생성 시도를 Phase A부터 분리한다

학생 응답 재시도와 늦게 도착하는 멘토 코칭이 같은 교사 메시지를 가리켜야 하므로, Phase A부터 교사 메시지에 안정적인 `turn_id`를 배정하고 각 명시적 생성 시도는 별도의 `generation_run`으로 기록한다. 학생 응답이 저장되기 전에는 완료 턴으로 세지 않으며, 같은 요청 ID의 재전송은 기존 실행을 반환하고 명시적 재시도만 같은 턴에 새 실행을 만든다. S3의 멘토와 S5의 비교가 이 식별 원칙을 이어받되, Phase A에 비교 테이블이나 시나리오 통합 설정을 미리 만들지는 않는다.

## Considered Options

- 실행 ID만 사용: 재시도할 때 코칭의 대상과 교사 메시지 연결이 바뀌거나 중복된다.
- 식별자 도입을 S3까지 연기: Phase A의 중복 방지·복구 계약과 데이터를 다시 이전해야 한다.

## Consequences

- 완료되지 않은 본문은 실행 기록에만 보관하며, 정상 학생 메시지나 분석 입력으로 승격하지 않는다.
- 기존 메시지 ID·본문·분석 정보는 보존하고, 과거 턴 연결이나 생성 이력을 추측하여 채우지 않는다.
- 기존 용어집의 턴 정의는 유지한다. 응답 대기 중에 식별자를 먼저 배정하는 것은 저장 계약이다.
