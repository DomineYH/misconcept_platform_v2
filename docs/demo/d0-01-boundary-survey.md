## 6. 미확인·리스크

1. **실행 미확인:** 운영 DB schema/history, 실제 middleware cookie 기본 속성, 배포된 worker 수, 파일 잠김·WAL 복제·dispose·취소 drain·AI egress는 확인하지 않았다. 소스의 설정 인자와 실제 브라우저/배포 동작을 구분한다.
2. **계약 v1 미확정:** DemoContext 필드/타입, namespace 전파 방식, lease 소유권·해제, 오류 코드/HTTP 상태, TTL/상한, reset 실패·만료·역할 전환 의미는 #190 결정 대상이다. 계획의 예시 값과 이름을 확정값으로 채택하지 않았다. #189의 fixture 명세 완성 여부도 이 작업에서 검증하지 않았다.
3. **CLI·추가 파일 쓰기 소유권 결정 필요:** 계획 §8과 §9.5만으로 `src/cli/cleanup_comparisons.py`, `src/cli/provider_smoke.py`, DB 관리 CLI, `src/api/routes/health.py`, `src/services/provider_reauthentication.py`, 비교 service 소비자 및 §4에 표시한 분석/utility 추가 전달부의 단독 쓰기 담당을 확정할 수 없다. 경계의 조정 담당은 §2에 지정했지만 그 담당에게 파일 쓰기 권한이 있다고 단정하지 않는다. #190에서 기존 단독 소유권을 침범하지 않도록 명시 배정해야 한다.
4. **관리자 범위 구체화 필요:** `src/api/routes/admin_groups.py`, `src/api/routes/admin_scenarios.py`, `src/api/routes/admin_about.py`, `src/services/admin_scenario_ops.py`, `src/services/admin_user_bulk.py`의 추가 guard/quota 패치가 필요한지는 자유 탐색 허용 정책에 달려 있다. 관리자 보호 조정은 #200으로 전달하되 변경할 파일 목록은 #190에서 고정한다. 모든 query를 새 tenant 방식으로 다시 작성하겠다는 제안은 아니다.
5. **namespace 전파 누락 위험:** UUID가 대체로 새로 발급돼도 probe/connection/User의 정수 ID는 DB별 반복된다. run UUID도 seed 복제 시 반복될 수 있다. `active_runs` 소비자는 generation stream뿐 아니라 세션 종료·계정 삭제·비교 이력/busy/정리에도 있다. registry만 바꾸고 소비자를 그대로 두면 안전하지 않다.
6. **늦은 저장 위험:** 현재 완료 함수는 DB의 running/삭제/종료 상태 등을 검사하지만 방문객 generation은 검사하지 않는다. `execute_call`의 shield된 원장 시작/완료, 분석 취소 cleanup, probe callback도 reset drain 및 lease 범위에 포함돼야 한다. 여기서 reset 경합이 해결됐다고 주장할 수 없다.
7. **비실행 경계도 외부 호출 위험:** AI 화면의 상태 조회와 catalog refresh/probe/비교 실행을 구별해야 한다. startup의 현재 정리는 상태 갱신이지 AI 재생성이 아니지만, demo에서 올바른 DB로 향하는지 미검증이다. smoke CLI는 승인된 execute만 호출하므로 항상 egress한다는 주장도 하지 않는다.
8. **브라우저 ID·cookie 위험:** 고정 CSRF reader가 기존 JS와 template inline script에 모두 있다. 세션 ID 기반 storage와 URL, 진행 중 fetch/SSE, 뒤로가기 복구는 방문객·세대 전환에 둔감하다. cookie 이름 설정만 바꾸는 것으로 완결되지 않는다.
9. **삭제 정책과 reset 구분:** 계정 삭제는 종료 이력 보존, 세션 삭제는 soft delete, 비교 삭제는 비용 원장 보존이다. reset의 세대 폐기 정책과 섞어서 기존 기록 보존 의미를 변경해서는 안 된다. 실제 race·회귀 결과는 미확인이다.
