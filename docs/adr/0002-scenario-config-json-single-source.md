# 시나리오 실행 설정은 `config_json` 단일 원본, 세션은 시작 시 스냅샷

학생봇·멘토·사후 분석 설정과 역할별 모델을 별도 템플릿·분석 틀 테이블에서 참조하던 구조를 버리고, 시나리오 안의 버전 붙은 `config_json` 하나를 실행 원본으로 삼는다. 검색·권한 필드(제목, 그룹, 상태)만 정규 컬럼에 남긴다. 새 세션은 시작 시점의 완성된 설정을 스냅샷으로 저장해, 이후 시나리오·모델 기본값 변경이 진행 중·종료 세션에 영향을 주지 않는다. 개별 컬럼과 JSON을 동시에 읽는 이중 원본 기간은 두지 않는다.

## Considered Options

- 템플릿·분석 틀 테이블 유지 + 시나리오별 오버라이드: 관리자가 "먼저 저장하고 선택하는" 절차가 남아 PRD 목표와 충돌.
- 설정 필드를 전부 정규 컬럼화: 자유 서술 위주의 설정에 비해 스키마 변경 비용이 큼.

## S2 설정과 운영 정책의 경계

수업 설정 스냅샷은 공개 문제·역할 지시·분류 기준·역할별 유효 모델 옵션과 문맥 턴 제한을 고정한다. 역할 기본값은 새 작성의 초기값일 뿐이며, 저장·실행할 때 현재 모델 기본값과 다시 병합하지 않는다. 제목·교과·대상 학년도 세션의 표시용 사본으로 보존하되 그룹 접근 권한·시나리오 비활성화·삭제·연결과 모델의 사용 권한은 현재 상태를 검사한다.

호출 시간 제한과 동시 호출 한도는 S1의 앱 운영 설정에 남겨 이후 시작 호출에 적용한다. PRD 10.1의 논리 구조에 있는 `runtime.role_timeouts`를 시나리오별 편집 필드나 두 번째 실행 원본으로 만들지 않는다. 수업 내용을 고정하면서 관리자가 서버의 운영 한도를 즉시 조정할 수 있도록 하기 위한 구분이다.
